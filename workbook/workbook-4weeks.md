# 4주 실천 워크북

『코드를 넘어서: 판단하는 개발자』(주민호 지음, 비제이퍼블릭) 부록

책의 도구는 각 장에 흩어져 있다. 이 워크북은 그 도구를 4주 순서로 묶은 것이다.
순서대로 따라 하면 '구현자'에서 '판단자'로 나아가는 습관이 만들어진다.

---

## 사용법

1. 1주차부터 순서대로 진행한다. 건너뛰지 않는다.
2. 각 도구는 채워 넣는 양식이다. 읽고 끝내지 말고 실제로 채운다.
3. 판단 로그(1주차)는 4주 내내, 그리고 그 이후로도 매일 작성한다.
4. 워드 파일은 표에 바로 타이핑할 수 있고, PDF는 인쇄해서 손으로 쓸 수 있다.

---

## 1주차 — 자기 진단: 나는 매일 무엇을 결정하는가

- [ ] 자가 진단 12문항으로 판단 성향을 파악한다 (10장)
- [ ] 매일 판단 로그 6줄을 채우며 결정 패턴을 관찰한다 (10장)

### 자가 진단 채점표

12개 상황에 대해 고른 선택지를 기록한다.
채점은 A = 2점, B = 2점, C = 4점, D = 1점. 총점 범위 12~48점.

| 영역 | 상황 | 선택 | 점수 |
|---|---|---|---|
| 1. 문제 정의 | 상황 1 | | |
| | 상황 2 | | |
| | 상황 3 | | |
| 2. 리스크 감각 | 상황 4 | | |
| | 상황 5 | | |
| | 상황 6 | | |
| 3. 우선순위와 가중치 | 상황 7 | | |
| | 상황 8 | | |
| | 상황 9 | | |
| 4. 복기와 성장 | 상황 10 | | |
| | 상황 11 | | |
| | 상황 12 | | |
| **총점** | | | |

**성향 집계** — A, B, C, D를 각각 몇 번 골랐는지 센다. 가장 많이 고른 것이 판단 기본값이다.

| A (즉시 실행형) | B (구조 선호형) | C (기준 설계형) | D (보류·회피형) |
|---|---|---|---|
| 회 | 회 | 회 | 회 |

내 판단 기본값:

> 점수가 낮다고 나쁜 개발자는 아니다. 핵심은 자기 판단의 기본값이 어디에 있는지 아는 데 있다.

### 판단 로그 — 매일 5분, 6줄

날짜:

| 항목 | 작성 |
|---|---|
| 1. 오늘의 결정 (Decision) | |
| 2. 대안 A / B | |
| 3. 내가 고른 것 (Choice) | |
| 4. 근거 2가지 (Reasons) | |
| 5. 리스크 + 중단 조건 (Risk + Stop) | |
| 6. 성공 측정 기준 (Metric) | |

*7일분을 준비했다. 워드·PDF 파일에는 날짜별 칸이 들어 있다.*

## 2주차 — 결정 기록: 판단에 형태를 부여한다

- [ ] 마이크로 ADR에 결정을 반 페이지 분량으로 기록한다 (2장)
- [ ] 범위 제외 3문장으로 '하지 않을 것'을 명시적으로 정한다 (3장)
- [ ] 측정 지표 1개로 성공과 실패의 기준을 정한다 (4장)

### 마이크로 ADR — 결정을 반 페이지로 남기기

| 대안 A | |

|---|---|---|---|

| ② | | | |
| ③ | | | |

## 3주차 — 성과 가시화와 보고: 판단을 말로 전달한다

- [ ] 성과 문장 변환기로 '했습니다'를 '바꿨습니다'로 바꾸는 연습을 한다 (5장)
- [ ] 30초 보고 템플릿을 회의에서 실제로 적용한다 (6장)
- [ ] 보고 품질 체크리스트로 보고 직후 자가 점검한다 (6장)
- [ ] 2주 추적 로그에서 1주차 결정의 결과를 관찰한다 (12장)

### 성과 문장 변환기 — '했습니다'를 '바꿨습니다'로

변환 공식: **활동 → 결과 + 대안 + 리스크**

핵심 3가지 — ① 무엇이 바뀌었는가(전→후) ② 어떤 대안 중 이것을 골랐는가 ③ 리스크는 무엇이었는가

| № | 변환 전 (내가 쓴 활동 문장) | 변환 후 |
|---|---|---|
| 1 | | |
| 2 | | |
| 3 | | |

### 30초 보고 — 회의에서 바로 쓰는 5문장

아래 5개 문장을 순서대로 말한다. 30초면 충분하다.

| № | 문장 | 내 답 |
|---|---|---|
| 1 | "결론은 ___입니다." | |
| 2 | "대안은 A와 B가 있고, 제가 추천하는 건 ___입니다." | |
| 3 | "핵심 리스크는 ___와 ___이고, 완화책은 ___입니다." | |
| 4 | "성공 기준은 ___이고," | |
| 5 | "___이면 멈추겠습니다." | |

*연습법 — 이번 주 매일 1회, 어떤 대화에서든 이 5문장 순서대로 말하는 연습을 한다. 출퇴근길 혼잣말도 좋다.*

### 보고 품질 체크리스트 — 판단이 전달되었는가

- [ ] 결론을 10초 안에 말했는가 (BLUF, Bottom Line Up Front)
- [ ] 옵션이 최소 2개 있었는가
- [ ] 리스크를 구체적인 형태(실패 모드 → 영향 → 완화책)로 제시했는가
- [ ] 성공 기준 + 중단 조건이 있었는가
- [ ] '모르는 것'을 숨기지 않고, 확인 계획을 함께 말했는가

*5개 중 3개 이상 체크되면 합격. 2개 이하면 다음 보고에서 빠진 항목을 의식적으로 채운다.*

|---|---|---|

## 4주차 — 배포·검증·자동화: 운영 판단 습관을 완성한다

- [ ] AI PR 검증 체크리스트로 AI 코드를 머지 전에 점검한다 (7장)
- [ ] 릴리즈 전 5문항으로 승인 전 최종 판단을 내린다 (8장)
- [ ] 자동화 설계 검토서로 자동화를 설계하기 전에 9줄로 구조를 잡는다 (9장)

### AI PR 검증 체크리스트 — 머지 전 8문항

AI가 만든 PR을 검토할 때, 이 8가지만 확인해도 가장 위험한 실수를 막을 수 있다.

- [ ] **논리** — 핵심 도메인 규칙 1~2개를 테스트로 못 박았는가
- [ ] **보안** — 입력 검증 / 출력 인코딩 / 권한 경계를 두었는가
- [ ] **예외** — 실패 경로(네트워크 에러, null, 타임아웃 등)를 테스트에 포함했는가
- [ ] **구성** — 설정값이 환경별(dev/staging/prod)로 분리되었는가
- [ ] **관측** — 문제를 감지할 로그 / 메트릭 / 알람이 추가되었는가
- [ ] **롤백** — 이 변경을 5분 안에 되돌릴 수 있는가
- [ ] **범위** — AI가 요청하지 않은 리팩터링이나 스코프 확장을 몰래 수행하지는 않았는가
- [ ] **설명** — 이 코드가 왜 맞는지 말로 설명할 수 있는가

> 마지막 항목이 핵심이다. 'AI가 짰는데요'는 설명이 될 수 없다.

### 릴리즈 전 5문항 — 승인 버튼을 누르기 전에

| № | 질문 | 작성 |
|---|---|---|
| 1 | 실패하면 어떤 문제가 발생하는가 (영향 범위: 사용자 수 / 매출 / 데이터) | |
| 2 | 롤백 경로는 있는가 (5분 안에 이전 버전으로 되돌릴 수 있는가) | |
| 3 | 중단 조건은 무엇인가 ('___이면 즉시 롤백한다') | |
| 4 | 성공과 실패의 기준은 무엇인가 (지표 / 로그 / 알림) | |
| 5 | 오너는 누구인가 (새벽에 알림이 울리면 누가 먼저 대응하는가) | |

### 자동화 설계 검토서 — 코드 전에 쓰는 9줄

| № | 항목 | 작성 |
|---|---|---|
| 1 | 자동화 범위 — 무엇을 자동화하는가 | |
| 2 | 인간 개입 지점 — 어디서 사람이 승인/확인하는가 | |
| 3 | 실패 모드 Top 3 | |
| 4 | 실패 반경 — 사용자 / 매출 / 데이터 / 보안 / 타 서비스 | |
| 5 | 되돌리기 — 5분 내 가능한가, 원격으로 가능한가 | |
| 6 | 알아차리기 — 해석 가능한 신호 3개 (지표 / 로그 / 알람) | |
| 7 | 조금씩 — 1% → 10% → 50% → 100% 단계별 확대 계획 | |
| 8 | 폭주 방지 — 반복 제한 / 회로 차단 한계값 | |
| 9 | 자동→수동 전환 — 중단 시 사람이 어떤 조건에서 어떻게 개입하는가 | |

> 9번이 가장 중요하다. 장애는 항상 자동화가 잘 돌아가던 중에 터진다.

## 4주 이후

판단 로그 6줄을 계속 작성한다.
한 달이면 패턴이 보이고, 석 달이면 기록이 쌓이며, 일 년이면 기록이 기준이 된다.
